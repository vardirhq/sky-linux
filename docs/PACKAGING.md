# Packaging

One codebase produces several package formats. The binaries are `sky-linux` (UI), `sky-daemon` (service) and a bundled, checksum-verified `rclone`.

| Format | How | Status |
| --- | --- | --- |
| `.deb` / `.rpm` / AppImage | `scripts/prepare-sidecars.sh && cd apps/desktop && npx tauri build` | ✅ Built, installed and run (see below). Released via `.github/workflows/release.yml`. |
| AUR | `packaging/aur/PKGBUILD` | Draft. Uses the system `rclone`. |
| Flatpak | `packaging/flatpak/io.github.vardirhq.SkyLinux.yml` | Experimental, see below. |

## What the packages contain

| Path | What |
| --- | --- |
| `/usr/bin/sky-linux` | Desktop app |
| `/usr/bin/sky-daemon` | Background service |
| `/usr/lib/sky-linux/rclone` | Private rclone (pinned version, checksum-verified). Kept out of `/usr/bin` so it never conflicts with a distribution's rclone, and preferred over an `rclone` in `/usr/bin` when both exist. |
| `/usr/lib/systemd/user/sky-daemon.service` | systemd user unit |
| `/usr/share/applications/Sky Linux.desktop` | Menu entry (English and Norwegian), from `packaging/linux/sky-linux.desktop.hbs` |

The deb's dependencies (`libwebkit2gtk-4.1-0`, `libgtk-3-0`, `libayatana-appindicator3-1`) are generated by Tauri. The rpm also requires them by soname.

The AppImage carries the same files inside it, including rclone.

## Verified so far (Ubuntu 24.04 container)

- All three formats build with `npx tauri build`.
- `apt install ./sky-linux_*.deb` installs cleanly. Launching `sky-linux` with **no daemon running and no rclone on `PATH`** starts `/usr/bin/sky-daemon`, which uses `/usr/lib/sky-linux/rclone`; the window opens on the Norwegian onboarding.
- `apt remove sky-linux` removes the program files and **leaves user data** (`~/.config/sky-linux`, `~/.local/share/sky-linux`) untouched.
- The AppImage runs (`APPIMAGE_EXTRACT_AND_RUN=1`, no FUSE in the container) and uses the rclone inside it.

Not yet verified: a real desktop session (tray icon on KDE, and on GNOME with the AppIndicator extension), the systemd user unit under a real user manager, Fedora/openSUSE installs of the rpm, and arm64.

## glibc

A binary needs the glibc it was built against or newer. Builds on Ubuntu 24.04 need **glibc 2.39**, which rules out Debian 12, Ubuntu 22.04 and Mint 21. Release builds therefore run on `ubuntu-22.04` (glibc 2.35), and the workflow fails if a binary needs anything newer.

## Releasing

1. Set the version in the root `Cargo.toml` (`[workspace.package] version`).
2. Optionally, run **Actions → Release → Run workflow** to build the packages as artifacts and test them.
3. Tag and push: `git tag v0.1.0 && git push origin v0.1.0`. The workflow checks that the tag matches the version, builds, checks glibc, smoke-tests the `.deb`, and creates a **draft** GitHub release with the packages and `SHA256SUMS`. Publish the draft by hand.

arm64 builds use GitHub's ARM runners. Set the repository variable `ENABLE_ARM64=true` to include them.

## Editions

One codebase can be built as different editions. An edition changes only presentation: the name, colours and wording. Sky Core, its safety rules and its tests are the same in every edition.

| Edition | Build | Package | Look |
| --- | --- | --- | --- |
| Sky Linux (default) | `npx tauri build` | `sky-linux` | Neutral blue |
| Telia Sky | `npm run tauri:build:telia` (in `apps/desktop`) | `telia-sky` | Purple, in Telia's spirit |

- Preview an edition in the browser with the demo backend: `npm run dev:telia`.
- The edition is set by `VITE_SKY_EDITION` (`apps/desktop/src/edition.ts`) together with a Tauri config overlay (`src-tauri/editions/<edition>.conf.json`) for the product and window name.
- Colours come from CSS tokens under `:root[data-edition="…"]` in `styles.css`.
- Both editions install `/usr/bin/sky-linux` and use the same data folders and background service, so their packages conflict: only one can be installed at a time.
- **Brand assets.** The Telia Sky edition uses a generic cloud icon and the app's own typeface. Telia's logo, typeface and name in a published build need Telia's permission. Until then this edition is for demonstrations, not for public release.

## Background service per format

- **deb/rpm/AUR:** `systemctl --user enable --now sky-daemon.service`. The app also starts the unit, or the binary directly, if it isn't running.
- **AppImage:** there's no system integration, so the app spawns `sky-daemon` itself, and it keeps running while the app sits in the tray. "Start on login" uses an XDG autostart entry through `tauri-plugin-autostart`.
- **Flatpak:** a sandboxed app can't install a systemd user unit. Open questions:
  - Use the Background portal (`org.freedesktop.portal.Background.RequestBackground`) to autostart the app with `--hidden`, and run the daemon as a child of the app process.
  - inotify on host paths needs `--filesystem=home` (or narrower), because portal document handles don't support recursive watching. Flathub reviewers may push back.
  - The Secret Service is reachable via `--talk-name=org.freedesktop.secrets`.

## Updates and uninstall

Updates come from the packaging system (apt/dnf/pacman/Flathub). There's no self-updater. Uninstalling removes program files only: `~/.config/sky-linux`, `~/.local/share/sky-linux` and all user files stay.
